# 表形式データのコンペの進め方

工程は ①〜⑦ の順に進める。各工程の完了条件を満たしてから次へ進む。
このコンペ固有の数値(採用基準・現状のスコア・ファイル名)は `CLAUDE.md` にある。

## 役割

| 役割 | 担うこと |
|---|---|
| 指揮官(ユーザー) | 承認だけを行う。承認が必要な事項は `CLAUDE.md` の一覧 |
| Claude 本体 | `CLAUDE.md` を読み、作業をエージェントに任せ、結果を `experiment-gate` の手順で判定する。指揮官には推奨と判断材料を1つずつ示す |
| エージェント(`.claude/agents/`) | 管轄のファイルの中で実験し、決まった形式で報告する |

## ファイルの構成

- ファイル名の先頭の番号を工程の番号にそろえる(`01_eda` 〜 `07_compare_predictions`)
- `03_*` は特徴量を作る関数の定義だけ。`04_*` が import して CV で学習し、OOF・test の予測・提出ファイルを保存する
- `05_*` は `04_*` を引数違いで呼ぶだけ。`06_*` / `07_*` は保存済みの予測を読むだけ
- CV の分割は全モデルで1つに固定する(例: StratifiedKFold(5, shuffle=True, random_state=42))。
  分割がそろっていないと、OOF 同士のアンサンブルも、対応のある検定もできない
- `notebooks/` は工程ごとの説明版。本番の `.py` と結果が一致することを確かめる

## 工程と完了条件

| 工程 | すること | 完了条件 |
|---|---|---|
| ① EDA | 件数・欠損・値の種類の数・値ごとの目的変数の率を見る。仮説を立てる | 次工程で試す施策がリストになっている |
| ② Baseline | 元の列をそのまま、各ライブラリの既定の扱いで学習する | 全モデルの OOF の基準値がある |
| ③ Feature Engineering | 元の情報を失わずに渡す施策から試す(下記) | 採用した施策が本番の構成に入り、列名の一覧を出力し直してある |
| ④ Train and Evaluate | 収束(学習率を下げ、early stopping で木の本数を決める)を確認する | 本番の設定で OOF と test の予測を保存してある |
| ⑤ Hyperparameter Tuning | 見落とし(既定値のままの引数、別の引数が先に効いている制約)を探す | 探索の結果を記録してある。誤差なら打ち止め |
| ⑥ Ensemble | 順位平均で混ぜる。モデル間の順位相関も見る | 対応のある検定を通った構成だけが残っている |
| ⑦ 判定 | `experiment-gate` の手順で採否を決める | 成功も失敗も記録してある |

## Feature Engineering の優先順位

1. 元の列を落とさずに渡す(カテゴリ列をそのまま渡す、など)
2. 値を丸めずに目的変数の率を渡す(厳密値 Target Encoding。必ず Out-of-Fold で作る)
3. 出現回数(Count Encoding)、粗い解像度のキー、桁ごとの列、ビン数の引き上げ
4. 四則演算・交互作用は最後。作る前に、本当に必要かを1組ずつ測る

列を減らす施策は慎重に扱う。目的変数との相関が小さい列でも、モデルには必要なことがある。

## アンサンブルと最終提出

- 単体のスコアが同水準のときだけ、相関の低いモデルが効く。単体の差が大きいと、相関が低くても下がる
- hill climbing の重みをそのまま採用しない。対応のある検定で有意な構成だけを残す
- Public LB の小さな上下では判断しない。採否は CV と対応のある検定で決める
- 最終提出の2本は、CV が最高の構成と、CV 上位のうちそれと予測が最も違う構成(test の予測の順位相関が最も低いもの)にする
