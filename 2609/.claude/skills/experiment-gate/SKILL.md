# 実験1本の手順

採用基準の数値、比較に使うスクリプト、承認が必要な事項は `CLAUDE.md` にある。

## 1. 着手前

1. `Log.md` と `CLAUDE.md` の「打ち止め」を読む。同じ施策が記録にあれば試さない
2. 所要時間を見積もる。`CLAUDE.md` で承認が必要とされる規模なら、見積もりを添えて指揮官に確認する
3. 本番の成果物を戻せるようにする(git のタグ、または `backup_<内容>_<日付>/` への写し)

## 2. 実行

1. 新しい施策は `04_*` に一時的な引数を足して試す。成果物は別の名前(`--tag` など)で保存し、本番のファイルを上書きしない
2. まず軽量スクリーニング(サブサンプル・fold を減らす・木の本数を減らす)で方向を確かめる。
   ただし「1値あたりの行数」が効果の前提の施策は、サブサンプルでは測れないので最初からフルで測る
3. 有望なものだけフルの CV で確認する。重いジョブは1本ずつ、バックグラウンドで実行する
4. 実行の前後で、本番の予測ファイルが変わっていないことを確かめる

## 3. 判定

AUC を目で比べない。本番の OOF と新しい OOF を、対応のある DeLong 検定で比べる。

| 比較 | 見るもの |
|---|---|
| 単体 | そのモデルだけを置き換えたときの差と z |
| アンサンブル | 本番のアンサンブルのうち、そのモデルだけを置き換えたときの差と z |
| 相関 | 本番のモデルとの順位相関(予測がどれだけ変わったか) |

- 採用: 単体またはアンサンブルで採用基準(差と z の両方)を満たし、アンサンブルが下がらない
- 誤差: 基準に届かない。不採用として記録する
- 悪化: z が負で有意。不採用として記録する
- 単体だけが伸びてアンサンブルが伸びないものは採用しない(予測が他のモデルに似ただけのことが多い)

## 4. 後処理

| 結果 | すること |
|---|---|
| 採用 | 本番の構成(作る列の一覧や固定のパラメータ)に組み込み、一時的な引数を消す。`--dump-features` で列名の一覧を作り直す。採否表を 〇 にする。README・ノートブックの数値をそろえる |
| 不採用 | 関数を `03_feature_engineering_AllCatalog.py` の「不採用(記録)」に、名前の末尾にモデル名を付けて移す。一時的な引数を消す。採否表を ✖ にし、理由を書く |

採否表と列名の一覧に矛盾がないことを `verify_status()` で確かめる。

## 5. 記録と報告

- 成功も失敗も記録する。エージェントは自分の記録ファイルに書き、Claude 本体が `Log.md` にまとめる
- 報告には、次を表で含める
  - 試した施策
  - 単体とアンサンブルの差・z
  - 判定
  - 本番を変えたかどうか
